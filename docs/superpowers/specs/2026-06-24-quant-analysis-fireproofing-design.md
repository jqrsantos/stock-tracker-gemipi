# Quant Analysis & Reporting UI Fireproofing Design

## Objective
To bulletproof the `data_fetcher.py` quantitative engine, ensuring it handles edge cases (like missing data, cash-rich balance sheets, and negative equity) with rigorous value investing principles rather than arbitrary defaults. Concurrently, improve the decision-making logic to prevent false "Sell" signals on 52-week highs, and upgrade the email report UI to a responsive, flexbox-based layout.

## 1. Quantitative Engine Fireproofing (`data_fetcher.py`)

### 1.1 ROIC Calculation Redesign
- **Missing Data Exclusion:** When iterating over historical income/balance sheet data to build `roic_history`, strictly filter out years where both `EBIT` and `Equity` are zero (or NaN). This prevents missing API data from skewing multi-year medians.
- **Invested Capital (IC) Base:** Remove the blanket deduction of all cash. IC will be defined strictly as `Stockholders Equity + Total Debt`. This prevents artificially inflated ROIC for cash-heavy companies and financials.

### 1.2 Valuation Logic & Graceful Failures
- **Remove Arbitrary Defaults in Cyclical Valuation:** Remove the hardcoded fallback of `eps_5yr_avg = 1.50`. If a cyclical/asset-heavy company has a negative or zero 5-year average EPS *and* a negative trailing EPS, it must immediately be flagged as `is_too_hard = True` with an intrinsic value of `$0.00`.
- **Target Multiple Reversion:** Remove the hardcoded P/E of 15. If target P/E is missing or absurdly high, fall back to the stock's actual 5-year average P/E, capped at a maximum of 25 to remain conservative without breaking structurally high-multiple businesses.
- **DCF Growth Rate Safety:** Cap the endpoint-calculated FCF CAGR at a realistic macroeconomic maximum of 15% for mature companies. If the base year (Year 5 ago) was negative or zero, fall back to a standard 8% growth rate rather than failing or projecting infinity.

### 1.3 Negative Equity Handling
- **Debt Load Measurement:** If `equity <= 0` (often due to aggressive share buybacks), remove the `Debt / Market Cap` fallback as the primary metric. Introduce a `Debt / FCF` or `Debt / EBITDA` metric as an internal sanity check. However, for the standard output, if equity is negative, we will output `Debt / Equity` as `999.0` (flagged) and rely on the AI LLM prompt to contextualize it as a potential buyback distortion rather than masking it.

## 2. LLM Decision Logic Escalation (`listener/main.py`)
- **52-Week High Protocol:** Inject an explicit directive into the system prompt: 
  > "52-Week High Protocol: If a stock is trading near its 52-week high, DO NOT automatically classify it as a SELL. High-quality compounders frequently hit new highs. Instead, escalate the stock for further investigation, closely examine its intrinsic value versus current price, and maintain a HOLD or BUY unless the quantitative script explicitly flags the valuation as 'Expensive'."

## 3. UI and Formatting Enhancements (`notifier.py`)
- **Responsive Flexbox Cards:** Refactor the `format_stock_cards` function. Wrap the stock cards in a flex container (`display: flex; flex-wrap: wrap; gap: 20px;`) and assign them `flex: 1; min-width: 300px;`. This ensures cards sit side-by-side on desktop views and stack vertically on mobile screens.
- **Markdown Table Fix:** Modify the pre-processing of `markdown_content` before passing it to the `markdown` library, or utilize a custom regex to convert ASCII/Grid tables generated by `tabulate` into standard HTML `<table>` elements, bypassing the `<pre><code>` wrapper that currently breaks formatting.

## Testing Strategy
- Run `data_fetcher.py` directly on UNH to verify ROIC stabilizes around ~16.5%.
- Run `data_fetcher.py` on a structurally unprofitable cyclical company to verify the `is_too_hard` flag triggers without hallucinating an EPS of $1.50.
- Execute a test run of `notifier.py` with mock Markdown containing ASCII tables to verify successful HTML table rendering.
